## 审查发现与建议验收

以下是代码证据，尚未在真实界面中复现，不等同于已修复。优先级与验收均为模型建议。

### 1. 高优先级：已完结筛选没有对应语义

- 证据：`VideoListTabView.swift:145` 的“已完结”分支设 `airingOnly = false`，与“全部”相同；`VideoRepository.ListFilter` 只有布尔值，SQL 仅实现 `更新至%` 筛选。
- 建议：明确区分全部、播出中、已完结，未知状态不能当作已完结。
- 建议验收：混合样本包含播出中、全集和未知状态，三档返回正确子集；切换选项后选中显示正确；与年代、类型、地区组合及清除筛选正常。

### 2. 高优先级：缓存设置未接入加载器

- 证据：`PosterLoader.swift:8` 的共享实例始终默认初始化为 300MB，容量是不可变属性；`posterCacheLimitMB` 在设置中保存和展示，但未传入该实例。加载器的零容量分支也只是跳过淘汰，写盘仍会发生。
- 建议：让保存后的容量约束实际生效；“关闭”应与项目要求保持一致，不能暗中变成无限缓存。已有缓存是否立即删除属于需明确的实现行为，不擅自扩大为清空用户数据。
- 建议验收：降低容量后实际磁盘占用受约束；关闭后新请求不新增磁盘缓存；重启后设置仍生效。使用临时缓存目录验证，不清理真实缓存来凑结果。

### 3. 高优先级：同步完成未触发剧集、电影页重载

- 证据：`VideoListTabView.swift:90` 的任务依赖 `reloadKey`，该 key 仅含分类、排序、筛选；没有像 ChartTabView 一样监听同步完成。页面 rows 是独立状态。
- 建议：建立明确的数据更新触发点，并处理数据库初始就绪、分页与筛选切换之间的任务时序。
- 建议验收：停留当前列表完成同步后，集数和海报更新，无需切页；初次数据库就绪后可加载；快速切换筛选不混入旧请求结果、不重复追加分页。

### 4. 中优先级：S3 镜像与坏图候选混用

- 证据：`VideoRepository.swift:710` 的候选 SQL 将所有 `http://` 判为坏图，包括允许的局域网桶地址；`SyncEngine.swift:382` 镜像失败会返回外源 https 地址，写库后该条退出坏图队列，因此注释所说“下轮再试镜像”没有对应入口。
- 影响：局域网镜像可能反复补图；桶暂不可用时虽能显示外源图，却不会自动补做镜像。
- 建议：区分可信自有桶地址、站方坏图和待镜像状态，采用最少必要持久化；不要为解决此问题放宽公网 ATS。
- 建议验收：已镜像的局域网 URL 不再触发外源补图；桶失败时保留可用外源图，恢复后能按明确重试机制完成镜像；重复同步幂等，鉴权失败和限频边界保持。使用模拟响应和临时数据库，真实桶操作需另有授权。
