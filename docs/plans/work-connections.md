- 长期多卡动画损害低内存／低空闲负载：使用有限时长的描边和位移动画，后台与减少动态效果关闭。

## 已核实身份归并（2026-10-29）

## 想看收藏跟随作品归并（2026-10-30）

- 未关注显示「想看」，已有关注显示「已关注 X/Y 个平台」；点击展开当前卡片的平台清单，部分关注可补充其余平台。新关注从本次操作时刻及最新快照开始，不补造过去事件。
- 我的想看、今日、本周、排期变动及计数使用与全部片单相同的身份／同名归并保护。归并输入为当前启用来源的活跃排期与已收藏的离线快照；合并卡附带尚未收藏的当前平台，便于发现并显式补充。今日／本周只由已关注且仍活跃的平台排期触发，未读只由已关注平台的真实事件触发。
- 不再以历史 group_id 决定显示或取消范围。保留旧 group_id、added_at、原站 release ID、变动事件及已读，不执行永久迁移；身份失效可拆回独立卡。补充关注使用 INSERT ON CONFLICT DO NOTHING，不更新已有收藏。
- 取消前明确平台清单及对应排期记录会被清除，只删除确认的 release ID；隐藏或关闭的平台不被旧 group_id 连带删除。用户取消后重新关注以新的关注时间起算。

### 🔴 致命弱点

永久合并收藏组会让身份撤回后难以拆分，现有按 group_id 取消更会删除未显示的平台。必须改为可重算的展示分组和按明确 release ID 取消，且不借归并重写事件／已读。

### 🟡 主要缺陷

未关注平台的日期不能让作品计入今日／本周；同源多 ID 和跨地区排期不能因收藏而绕过归并保护；列表先分页再归并会导致页头计数不一致。弹窗期间来源关闭或刷新也不能扩张取消范围。

### 🟢 改进建议

同一数据库队列内计算候选键，SQL 先按已关注平台计算筛选／计数，再返回同组当前平台供补充关注。收藏写入及精确取消使用事务；界面冻结确认目标并在提交时排除已关闭来源。测试分别覆盖旧记录保留、补充关注基线、跨页计数、未关注排期排除、撤片／身份冲突与隐藏平台取消隔离。

### 📋 审查总结

方案可执行，展示归并与永久收藏身份必须分开。无需新数据库表、网络请求或自动关注；核心验收是同一作品只计一次，同时每个平台的关注历史完整独立。
