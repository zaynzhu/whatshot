# 新片待播与数字发行时间线

设计日期：2026-10-28；调研样本采集于 2026-10-27。用户授权继续探索、给出完整设计，并实施已有证据支持的部分。

## 目标与交付范围

新增「即将上线」标签页，回答作品在哪个平台、哪个地区、哪一天、几点计划上线。海外单片购买／租赁同样属于上线，不局限订阅片库。未知日期与未知时刻必须明确展示，不制造午夜时间。

本次实施国内三源：优酷电影／剧集、爱奇艺待播、腾讯片库与 VIP 排期，以及本地存储、独立刷新、来源开关、时间线、原站入口。芒果按用户决定不接入；海外新增美国数字发行报道视图，边界与实测见文末；不接入搜索摘要或填假数据。参考项目均只读，不修改 WhatsNew／PixelReel 或它们的数据库。

## 页面与交互

- 新增「即将上线」，沿用现有深色与琥珀主题、海报缓存。
- 来源筛选：全部／优酷／爱奇艺／腾讯；类型筛选：全部／电影／剧集。
- 三个视图：今日与未来、待定档、近期排期。近期看最近 14 天，不宣称已可播放。
- 按日期分组，日内已知时刻升序、未知时刻置后；无日期永远不进入某一天。
- 卡片展示海报、片名、平台／地区、时刻或「时间待公布」、来源原文、核实时间；点击打开原站。
- 同作品跨平台聚合为一张卡，逐平台展示日期、时刻与原站入口；来源身份仍各自保留，不自动加入 butai0 追剧库。
- 页面提示「平台公布排期，不保证已可播放」。首次未同步、全源关闭、筛选为空、同步失败分别呈现。
- 失败保留旧快照，显示失败来源与最近成功时间。先聚合再分页，每次最多 60 部作品，可加载更多；切换筛选令旧查询失效。
- 来源设置和刷新状态在本页可见；自动同步开关沿用应用现有同步间隔。

## 海外数字发行的完整语义

先研究美区，不能称为全球上线。同一时间线中以地区和发行方式区分：

| 发行方式 | 语义 |
|---|---|
| 预购 | 可以付款但不能看，不算已经上线 |
| 数字购买 | 单片购买开放 |
| 数字租赁 | 单片租赁开放 |
| 数字付费 | 来源只说明 Digital／VOD，不猜购买与租赁同时开放 |
| 订阅 | 进入订阅片库，可以晚于数字购买 |

实体蓝光／DVD 不进入该标签页。美国仅公布日期时保存当地发行自然日，标「美区日期」，不假设午夜后换算北京时间；只有来源同时给出时刻和时区才允许转换。官宣、报道、预测独立标记，美区报道进入合并时间线时逐卡标明官宣状态未核实，不作为精确时刻。

原设计接入门槛（此次已取得对应样本，首版改为隔离展示报道而非宣称逐片官宣）：拿到未来数字发行、订阅发行、预测日期、改期各一例真实响应；核对地区、日期含义、稳定身份／原站链接、分页及空列表语义；低频复读成功；不依赖账号、支付或验证码。达到后才启用来源，不以搜索缓存代替实时契约。

## 数据模型和日期

使用独立 `upcoming_releases`、`upcoming_source_state` 表，不写 videos 首播日，不给 butai0 或外部热度加入预约数。

排期保留来源、来源作品 ID、大类、片名、平台、地区、时区、发行方式、可空日期与时分、原文、海报、原站链接、观察时间、来源明确可看状态。身份由来源＋作品 ID＋大类＋地区＋发行方式组成，片名不是身份。

日期与时分分开存；时分依附有效日期。优酷不靠系统时钟推断可看，爱奇艺 isOnline 仅表示来源报告已上线，不保证用户账号权益。源改为待定时清除旧排期，不保留已经撤回的日期。

中国来源显式用 Asia/Shanghai。相对日期依据可信观察日；过旧响应不生成「今天／明天」的绝对日期。无年份月日默认当前年，仅年末到次年年初窄窗口进位，昨日残留不能跳到明年；无法消歧保留原文。严格校验公历、小时、分钟，拒绝 2 月 30 日、24:99、孤立时刻。

当前来源快照完整替换；从完整新快照消失的旧项退出当前片单，不判定已上线或下架。移除超过 30 天再清理，避免无界累积。当前阶段不加独立改期消息中心。

## 同步与失败边界

- 待播同步独立于 butai0 探活，后者不可达不能阻断它。
- 复用现有低频调度时机，不新增空转计时器。自动同步关闭时待播同样不自动请求；手动刷新允许。
- 每源共享独立 RateLimiter，至少 2 秒；请求有超时、大小限制和取消检查。优酷匿名令牌只在内存中，不读取浏览器 Cookie、不打日志。
- 每源完整分页及契约验证通过后才事务提交。超页数、重复游标、组件缺失、解析失败、取消都保留旧快照。
- 来源之间独立，失败不回滚其他源的完整成功批次。优酷 token 只重取一次，403／429 不高频重试。
- 来源关闭后不发新请求、不混入旧缓存；运行中设置变更取消旧轮次。
- 海报只接受 HTTPS；对已验证优酷 CDN 升级协议，其他 HTTP 留空。爱奇艺仅对已知同素材竖版缩略图升级尺寸。无新增公网 ATS 豁免。

## 红队自审

### 🔴 致命弱点

全部影片都精确到几点的假设已被实测推翻，必须保留未知精度。预购、影院公映、数字买租、订阅上线混用会使时间线失效，必须保留地区与发行方式。半批失败不能清空数据，必须完整批次才提交。

### 🟡 主要缺陷

| 问题 | 等级 | 修正 |
|---|---|---|
| 一次成功推断长期稳定 | 高 | 真实复读与失败测试，长期稳定性明确未证明 |
| 优酷节点混入非预约 | 高 | 校验预约身份，不靠栏目位置 |
| 执行 Nuxt 远端代码 | 高 | 仅接受数据字面量，表达式／调用拒绝 |
| 跨平台复制时刻 | 高 | 每个平台独立日期精度 |
| 窄窗口标签挤压 | 中 | 导航适配窄窗 |
| 调度关闭仍启动同步 | 中 | 待播单独检查自动同步开关 |

### 🟢 改进建议

先交付国内三源的可运行闭环，海外保留明确接入门槛，不做空壳采集器。用真实字段构建最小测试样本，验证不依赖生产库。未定档多是现实，不推测填满。

### 📋 审查总结

国内三源可实施；海外仍需实测入口。最高优先级是日期语义、原子快照和独立失败边界。否则有数据的界面仍会误导用户。

## 跨平台聚合修正（2026-10-28）

用户要求相同作品合在一起展示，替代首版每个平台各占一张卡的行为。

- 以完整标题（只去首尾空格、折叠大小写）、电影／剧集大类、地区、发行方式组成展示分组。保留季数、年份、副标题、版本字样。数据缺少统一豆瓣／IMDb ID，因此这是保守的标题分组，不是权威作品身份匹配；异名作品暂不合并。
- 同一个平台存在多个不同 ID 同名时，整个候选组拆开，避免明显歧义。各来源原始记录不改写、不删除，可随源撤回或改名重组。
- 时间线选择筛选范围内最近的今日／未来平台日期；无未来时选最后已知日期。仅全部平台均无日期才放入待定档。卡片内列出全部参与分组平台的完整排期，各家精度不互相补齐。
- 平台筛选只保留选中平台，关闭来源同理；按作品分组后分页，每页最多 60 部，避免跨页重复。SQL 完成聚合，应用不全量加载片单。
- 本轮新增分组测试验证三平台合卡、不同日期、未知时刻、待定档去重、平台筛选、近期排期、跨页完整性、同源同名歧义及类型／季数隔离。
- 本轮再次真实匿名读取，三家完整成功：222／149／209 条，与上轮一致，用时约 61 秒。这是短期复读证据，不等于长期稳定承诺；三家均非公开稳定契约，结构变化或风控仍可能导致失败，失败保留旧缓存并标注。

### 🔴 致命弱点

将标题分组当作权威身份、或把一个平台的时分复制给其他平台，会制造错误排期。只做展示聚合，原始来源不合并写库，每平台排期独立。

### 🟡 主要缺陷

| 缺陷 | 严重程度 | 处理 |
|---|---|---|
| 跨平台完全同名同类型仍可能是不同作品 | 高 | 保留版本文字，同源冲突不并；不宣称精准身份匹配 |
| 先分页再合并会重复或漏平台 | 高 | SQL 先分组，选中作品后返回其全部平台记录 |
| 少量成功推断长期稳定 | 高 | 报告实测次数与当前边界，不给长期成功率 |

### 🟢 改进建议

只在未来来源有可靠统一作品 ID 时提升身份匹配；当前不做模糊标题搜索或跨平台日期推测。

### 📋 审查总结

按用户要求修正重复卡片；明确标题分组局限，保留独立排期与来源信息。芒果从接入计划移除。

验收：分组相关 16 项测试报告通过（2 项外部验证默认跳过），三家真实复读单独通过。release 打包与签名验证通过，实际窗口已确认《玩具总动员5》只展示一张卡，包含优酷 10:00、爱奇艺时间待公布、腾讯待定档三个独立入口。


## 腾讯 VIP 排期修正（2026-10-28）

用户指出真实需求入口是 [腾讯电影首页](https://film.video.qq.com/) 的「VIP即将上映」。首版仅接片库，结论“腾讯全部待定档”只适用于该片库接口，不能推广到腾讯整个网站。

- 保留 `getMVLPage` 电影／剧集完整分页；新增首页使用的公开匿名 `GET https://film.video.qq.com/x/autovue/film_index/cgi/getModList`。
- 参数 `_param={"pageContext":"new_marklabel=1","modNum":5}`、`env=online`，沿响应 `pageContext` 寻找 `type_58` 且标题为「VIP即将上映」的模块。实测第 2 页返回完整栏目 `list`，网页直接将此列表交给横向滑动组件，没有栏目内续页；这里的覆盖范围是该首页栏目，不是全站预约库。
- `cms_data.type=1` 电影、`2` 电视剧；`3` 动漫与 `10` 综艺不擅自映射到电影／剧集。本次匿名样本 100 张卡，69 张属于已支持大类。与浏览器现存页面对照同一作品 cid、标题和 show_date，无需登录、Cookie、浏览器脚本执行。
- 结构化 `show_date` 按北京时间严格解码 `yyyy-MM-dd HH:mm:ss`；`data_type=text` 时解析原文，仅日期就保留未知时刻，敬请期待不赋日期。腾讯前端把 `23:59:59` 显示为当天 24:00，存为次日 00:00；真实 `00:00:00` 也属于明确公布的午夜，并非缺省补零。
- 两入口仅按 cid 对齐，分类冲突报错；VIP 为该 cid 提供独立排期和原始文字，VIP 独有电影／剧集也保留，同名不同 cid 不合并。来源成功改为敬请期待或移出 VIP 栏目时，旧日期随整源快照清除，片库仍在则保留待定档。
- 两入口共用腾讯限频器（≥2 秒）。VIP 缺栏、游标重复、超过上限、格式变化或网络失败都不提交半份腾讯结果，沿用来源错误标记与旧快照。无新增定时器或数据库表。

### 🔴 致命弱点

仅保留片库会遗漏用户明确需要的时分；拿 `publish_date` 代替又会把影院日期混进平台时间线。必须读取经栏目验证的 `show_date`，两个入口完整成功才发布。

### 🟡 主要缺陷

| 缺陷 | 严重程度 | 处理 |
|---|---|---|
| 首页栏目含综艺与动漫 | 高 | 按来源 type 1/2 收窄，不全当电影 |
| 同名多个 cid 或同 cid 分类冲突 | 高 | cid 对齐，冲突失败，不标题补日期 |
| VIP 请求失败导致旧日期清空 | 高 | 任一入口失败保留整份旧腾讯快照 |
| 100 张栏目样本不等于全站覆盖或长期稳定 | 中 | 保留片库补覆盖，明确栏目范围与短期验证边界 |

### 范围与语义

- 地区筛选提供「全部地区」「中国大陆」「美国 · 发行报道」，默认合并展示全部地区；来源开关与自动同步沿用原机制。
- 读取上月、本月、下月已发布 VOD-only 日历，再对近期与未来候选按详情链接 slug 批量获取详情。详情 page ID 作为来源身份；标题取详情 title，不用带编号的图片文件名。禁止标题搜索匹配。
- 只采详情中明确的 VOD / PVOD Release Date，不采 Theater Date、SVOD、预购或实体碟日期。统一 `region=US`、`releaseType=digital`，表示数字付费，未区分购买／租赁或具体零售商；所有时分为空、时区未知，不转换为北京时间。
- 月历与详情冲突以当前详情 VOD 日期为准；详情明确 TBA 清除旧日期。窗口覆盖过去 14 天至下月末，来源不在该窗口的记录退出当前快照，不推断上线／下架。
- 日期只是美国自然日；“今日／近期”的查询边界按美国东部日历划分，界面明确提示。这是筛选基准，不是影片上线时区。
- 全部条目标为「媒体报道 · 官宣状态未核实」。真实反例：Primetime 详情写 11 月 3 日，但同站报道明确片方未确认。不能因详情无 estimated 字样就升级成官宣。此范围替代原设计等待逐片官宣的接入方式，报道在默认合并视图中保持美国地区与官宣未核实标签。
